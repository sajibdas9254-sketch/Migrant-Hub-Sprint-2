# API Contract — Migrant Hub

**Version:** 1.2
**Agreed:** 8 September 2026
**Status:** Fixed for Sprint 2. Changes require both teams present.

This document is the agreement between the frontend and backend teams. The frontend writes
its mock data in exactly these shapes. The backend builds endpoints that return exactly
these shapes. We do not connect them this sprint — but when we do in Sprint 3, they should
fit together without changes.

---

## Conventions

| Rule | Value |
|---|---|
| Base URL | `http://localhost:4000/api` — same port as the Tour API lab |
| Format | JSON, both directions |
| Field naming | `camelCase` — `createdAt`, never `created_at` |
| IDs | String. Arrays use `"1"`, `"2"`. MongoDB will use its `_id`, exposed as `id`. |
| Dates | ISO 8601 string — `"2026-09-03T14:20:00.000Z"` |
| Lists | Return a JSON array, not an object wrapping an array |

### Status codes

| Code | When |
|---|---|
| `200` | Successful GET and PATCH |
| `201` | Successful POST — resource created |
| `204` | Successful DELETE — no body returned |
| `400` | Bad input — missing or invalid field |
| `404` | Resource does not exist |
| `500` | Server error |

### Error shape

Every error returns the same structure:

```json
{
  "error": "Validation failed",
  "details": ["title is required", "body exceeds 512 words"]
}
```

`details` is optional and only present for validation errors.

Note: the Tour API lab returned errors inconsistently — sometimes `{ "message": "..." }`,
sometimes a plain string `'Not Found'`. We are standardising on one shape here on purpose,
so the frontend can handle every error the same way. Worth mentioning in the code
self-assessment as a deliberate improvement on the lab.

## Entity: Post

The core entity of the product.

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string | yes | Generated by the server |
| `title` | string | yes | Max 120 characters |
| `body` | string | yes | **Max 512 words** |
| `author` | string | yes | A display name. No authentication this sprint. |
| `createdAt` | string | yes | ISO date, set by the server |
| `category` | string | yes | One of the allowed categories below |
| `tags` | string[] | no | Defaults to `[]` |
| `aiTeaser` | string | no | 1–2 sentence overview. Written by hand in mock data this sprint; generated in Sprint 3. |
| `communityId` | string \| null | no | `null` if the post is not in a community |
| `imageUrl` | string \| null | no | |

### Allowed categories

`Housing` · `Paperwork` · `Transport` · `Food` · `Study` · `Community` · `Places`

`Places` was added after the Sprint 1 AI spike, which found that a post about visiting
somewhere in Helsinki had no category to sit in.

### Example post

```json
{
  "id": "1",
  "title": "A Ferry Trip to Suomenlinna",
  "body": "Today, I visited Suomenlinna, a beautiful historic sea fortress near Helsinki...",
  "author": "Prabhleen Kaur",
  "createdAt": "2026-09-03T14:20:00.000Z",
  "category": "Places",
  "tags": ["Suomenlinna", "Day Trip", "HSL"],
  "aiTeaser": "A short ferry ride from Helsinki city centre reaches Suomenlinna, a historic sea fortress with stone walls and wide sea views.",
  "communityId": "1",
  "imageUrl": null
}
```

## Endpoints — Posts

### `GET /api/posts`

Returns all posts, newest first.

**Query parameters** — all optional, and combinable:

| Parameter | Example | Effect |
|---|---|---|
| `category` | `?category=Housing` | Only posts in that category |
| `communityId` | `?communityId=1` | Only posts in that community |
| `search` | `?search=bus card` | Title and body contain the text |
| `limit` | `?limit=3` | Return at most this many |

**Response `200`** — array of post objects.

```json
[ { "id": "1", "title": "A Ferry Trip to Suomenlinna", "...": "..." } ]
```

An empty result is `200` with `[]`, not a `404`.

### `GET /api/posts/:id`

**Response `200`** — one post object.
**Response `404`** — `{ "error": "Post not found" }`

### `POST /api/posts`

**Request body:**

```json
{
  "title": "My First Visit to Oodi Library",
  "body": "Today, I visited Oodi Library in Helsinki...",
  "author": "Yun Wang",
  "category": "Places",
  "tags": ["Oodi", "Library"],
  "communityId": "1"
}
```

The server sets `id`, `createdAt`, and leaves `aiTeaser` as `null` this sprint.

**Response `201`** — the created post, including its new `id`.
**Response `400`** — validation failed. Missing `title`, `body`, `author` or `category`;
`body` over 512 words; `category` not in the allowed list.

### `PATCH /api/posts/:id`

Send only the fields you want to change. Fields not sent are left unchanged.

```json
{ "title": "A Ferry Trip to Suomenlinna (updated)" }
```

**Response `200`** — the updated post.
**Response `404`** — post does not exist.

We use `PATCH` rather than `PUT` because that is the pattern used in the Tour API lab: a
partial update, not a full replacement.

### `DELETE /api/posts/:id`

**Response `204`** — no body, matching the Tour API lab.
**Response `404`** — post does not exist.

## Endpoints — Communities

| Method | Path | Returns |
|---|---|---|
| `GET` | `/api/communities` | Array of communities |
| `GET` | `/api/communities/:id` | One community, or `404` |
| `GET` | `/api/communities/:id/posts` | Array of posts in that community |
| `POST` | `/api/communities` | `201` with the created community |
| `PATCH` | `/api/communities/:id` | `200` with the updated community |
| `DELETE` | `/api/communities/:id` | `204`, no body |

`POST` requires `name` and `description`.

---

## Endpoints — Must Do

| Method | Path | Returns |
|---|---|---|
| `GET` | `/api/mustdo` | Array of items, sorted by `order` |
| `GET` | `/api/mustdo/:slug` | One item by slug, or `404` |
| `POST` | `/api/mustdo` | `201` with the created item |
| `PATCH` | `/api/mustdo/:slug` | `200` with the updated item |
| `DELETE` | `/api/mustdo/:slug` | `204`, no body |

Note that Must Do items are addressed by `slug`, not `id`. It makes the frontend routes
readable — `/must-do/dvv` rather than `/must-do/1`.

---

## Not in this contract

Deliberately absent, because they are Sprint 3 work:

- Authentication endpoints. Login and registration are simulated in the frontend only.
- AI generation endpoints. The `aiTeaser` and `tags` fields exist on the Post entity so the
  frontend can display them from mock data, but nothing generates them this sprint.
- Admin endpoints.
- Pagination beyond the simple `limit` parameter.

---

## How to change this document

If either team finds something missing — a field a screen needs, an endpoint that does not
exist — do not patch it locally. Raise it, both teams agree the change, bump the version at
the top, and commit it. One team quietly editing their own copy is how the two halves end up
not fitting together in Sprint 3.

**Owners:** Sehwinder Singh (data model) and Yun Wang (endpoints), with the frontend team
reviewing that every screen has the data it needs.
